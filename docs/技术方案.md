# 技术方案 · 派遣岗位需求与到岗交接业务核对助手

> 阶段 4／9 方案设计文档。**本阶段只做设计，不开发系统、不写业务代码。**
> 本文所有内容为合成演练设计，需求均为待验证假设；只读核对与人工交接，不代表真实授权、业务执行或客户验收。
> 证据编号 `fNN` = `fsg-assignment-fNN`，来源 `source/discovery-report.md`。`f12` 为虚构演练样本，不作基线。

## 1. 要解决的那一个痛点

电话里改了岗位条件（技能要求、夜班班次），需求单没回写，交接单仍引用旧版本，人到岗才发现对不上、再返工；中间全靠口头提醒和群消息，查不到「谁在哪一刻改了什么」（f10、f11、f50、f01）。

一句话概括：**变更没落单、版本没闭环**。

其他症状都是从它派生出来的，不单独立项：回填时间不能当发生时间（f13）、三类工具没有统一关联编号（f30）、复核全靠人工且工时没按单记（f14）、两张汇总表数量／状态／截止时间对不上（f53）、统计口径未定。所以本方案的所有能力都必须能回到「变更有没有回写、版本有没有确认、交接有没有留痕」这三个断点上。

## 2. 设计原则

1. **只读**：只处理脱敏只读导出，不写回、不发外部消息、不开执行接口（f32）。
2. **人工确认优先**：输出一律是草稿，正式确认由业务负责人完成，模型没有审批权（f22、f41）。
3. **不默认通过**：版本或关键字段确认不了就进人工队列、必要时暂停（f44）。
4. **可追溯**：每条结果关联来源位置和人工复核记录（f42）；缺失值与未确认值分开（f31）。
5. **规则先行**：能量化的判断交给确定性规则，模型只做非结构化文本抽取。
6. **口径先定**：统计口径（按需求单计数、发生时间起算、返工按退回次数）未定之前，不给任何改善结论。

## 3. 总体架构

```
[数据接入层]  脱敏只读导出（批次号 / 岗位代号 / 来源位置 / 两个时间戳）
      │  断连即停，不用缓存旧数据冒充
[知识层]      知识库（知识图谱）：岗位硬条件、规则版本、关联编号、确认状态
      │  关联编号缺失 → 不猜、不拼接 → 降级人工比对
[能力层]      ① 场景范围核对  ② 资料与版本核对  ③ 交接草稿整理
      │  见第 4 节；三个能力共用同一套提示词约束
[评测层]      Harness 固定样本回归：未确认误判为已确认 = 0 容忍
      │  每次提示词或规则变更都要跑
[交付层]      一页缺项清单（含来源位置，不给长摘要 f15）、交接草稿
      │
[人工确认闸门] ◇ 版本／关键字段能否确认？ ◇ 来源与复核记录齐全？ ◇ 到岗条件一致？
      │  否 → 人工队列／暂停（f44）
[交接]        交接单列最新版本、未确认事项、截止时间（f23），接收人签收（f20）
```

详细图见 `docs/架构图.md`（Mermaid）与 `docs/架构图.svg`（竖向，菱形为人工判断点）。

## 4. 智能体系统设计（本阶段只定义职责，不实现）

三个「能力」先按页面分工写，不预设跑几个模型；等阶段 5 构建集成再决定实现方式。三者共用同一份系统约束与输出 schema，见 `docs/提示词.md`。

### 能力 1 · 场景范围核对

| 项 | 内容 |
|---|---|
| 输入 | 批次号、试点岗位清单、场景边界条款 |
| 输出 | 本单是否在试点范围内、命中的边界条款、排除原因 |
| 允许 | 只读比对、标记「范围外」 |
| 禁止 | 扩大试点范围、跨批次取数、把范围外单据混进结果 |
| 人工卡点 | 试点岗位清单与授权确认人由业务负责人锁定后才可启动（f05） |
| 失败降级 | 清单缺失 → 整批暂停，不默认按全量处理 |

### 能力 2 · 资料与版本核对（核心）

| 项 | 内容 |
|---|---|
| 输入 | 需求单版本、交接单版本、规则版本、电话／群消息文本、来源位置 |
| 输出 | 结构化变更要素、版本不一致项、一页缺项清单、每条的来源位置与确认状态 |
| 允许 | 抽取、比对、列缺项；区分「缺失」与「未确认」（f31） |
| 禁止 | 覆盖单据原值、省掉确认、自动写回、自动判定责任、把未确认项算到接收方头上（f14、f25） |
| 人工卡点 | 版本或关键字段确认不了 → 人工队列／暂停（f44）；每条结果须挂来源与人工复核记录（f42） |
| 失败降级 | 关联编号缺失（f30）→ 转人工比对并留痕；抽取不出 → 标「未识别」，不猜 |

### 能力 3 · 交接草稿整理

| 项 | 内容 |
|---|---|
| 输入 | 已确认的版本、未确认事项、截止时间、接收人 |
| 输出 | 交接单草稿（最新版本／未确认项／截止时间），一页呈现（f23、f15） |
| 允许 | 生成草稿、附来源位置 |
| 禁止 | 对外发送、向真实人员发送安排、自动决定录用或派遣资格、只回一句「已处理」（f05、f52、f23） |
| 人工卡点 | 对外承诺由业务人员确认（f52）；正式结论须授权人员确认（f41） |
| 失败降级 | 任一必填项未确认 → 不出草稿，转人工队列 |

### 模型职责边界（一句话）

模型 = 把口头变更变成可比对字段 + 生成草稿；**不是**判断责任、不是确认版本、不是审批、不是执行。判断点 1／2／4 可由能力协助，判断点 3／5／6 全部留给人工，对应现状流程图的六个菱形。

## 5. 数据版本与关联键

| 对象 | 版本规则 | 依据 |
|---|---|---|
| 需求单 | 电话变更须回写生成新版本并标记确认状态；回写责任人与时限待补 | f23、f24 |
| 交接单 | 必须引用最新已确认版本，列未确认项与截止时间 | f23、f20 |
| 规则版本 | 岗位硬条件与规则分开存档；过期来源不覆盖已确认新版本 | f34 |
| 时间戳 | 业务发生时间 ≠ 系统接收时间；回填时间不作发生时间 | f13、f34 |
| 关联键 | 服务台／台账／文件库统一编号；取哪个字段、完整率多少待补 | f30、f31 |
| 确认状态 | 缺失值、未识别值、未确认值三类分开，不合并成「无」 | f31 |

## 6. 数据与权限矩阵

| 数据／动作 | 一线服务 | 交接协调 | 质量复核 | 业务负责人 | 客户现场 | 模型 |
|---|---|---|---|---|---|---|
| 脱敏只读导出 | 读 | 读 | 读 | 读 | — | 读 |
| 提交变更草稿 | 提交 | 提交 | — | — | — | 生成 |
| 版本／未确认项确认 | — | — | 签认 | **正式确认** | — | **禁止** |
| 交接单写回／对外承诺 | — | — | — | 确认后由业务人员执行 | — | **禁止** |
| 暂停试点／叫停 | — | — | 叫停 | 定范围 | 确认用途 | — |
| 留存期限与删除审批 | — | — | — | 审批 | — | — |

依据：f22（模型无审批权）、f41（授权人员确认）、f04（质量侧叫停、客户侧确认用途）、f52（对外承诺由业务人员确认）。

## 7. 接口契约（设计契约，非可运行代码）

| 契约 | 方法／形态 | 输入 | 输出 | 失败／越权 |
|---|---|---|---|---|
| 只读导出 | 只读查询 | 批次号、岗位代号 | 脱敏字段、来源位置、两个时间戳 | 断连即停；越权返回拒绝并留痕 |
| 变更要素抽取 | 本地模型推理 | 电话／群消息文本 | 变更要素 JSON＋原文定位 | 抽不出标「未识别」转人工 |
| 版本比对 | 确定性规则 | 三类版本号、关联编号 | 不一致项＋一页缺项清单 | 字段缺失标「缺失」；编号缺失降级人工 |
| 结果签认 | 人工动作 | 草稿＋来源＋复核记录 | 确认／退回 | 缺来源或缺复核记录一律不签认 |

**不开放**：写回接口、外部消息接口、执行接口、录用／派遣资格判定接口（f05、f32、f52）。
**统一错误分类**：范围外／未识别／字段缺失／版本未确认／来源缺失／越权，六类都进人工队列，不静默降级为「通过」。

## 8. 工具限制与降级策略

- 只处理本场景合成资料，具体业务规则、真实接口、验收条件仍需核实。
- 系统建议不覆盖原值、不省确认（f14）；同一单数量／状态／截止时间以原始单据为准，不用两张汇总表互相比（f53）。
- 任一环节拿不准 → 人工队列 + 必要时暂停（f44）；宁可不出结果，不出错结果。
- 反馈与投诉登记后进入周复盘（f54、f55），复盘结论只更新规则与评测样本，不自动改线上数据。

## 9. Harness 评测设计

| 项 | 设计 |
|---|---|
| 样本 | 一个批次内的固定样本，含「已确认新版本」「电话改条件未回写」「临时加夜班未同步」「关联编号缺失」「来源缺失」五类 |
| 硬指标 | 未确认被误判为已确认 = **0 容忍**；不得出现无来源的结果 |
| 观察指标 | 缺项召回率、来源可追溯率、人工退回次数、确认完整率 |
| 触发时机 | 每次提示词、规则、知识库条目变更后全量重跑 |
| 通过条件 | 业务验收（f02）与质量验收（f42）合并成一张清单共同签认；效果评估用工时＋返工次数＋确认完整率多指标（f51），不只看清单完整率 |

## 11. 试点、预算与决策边界

- 一个批次（f05）；30 个岗位列出硬条件与待确认项、变更影响清单（f02）。
- 四周、两名骨干、每周不超四小时，超了重新评估（f03）。
- 范围由业务负责人定、质量侧保留叫停权、客户侧确认结果用途（f04）。
- 不自动决定录用或派遣资格、不向真实人员发送安排（f05、f52）。

## 13. 阶段边界
